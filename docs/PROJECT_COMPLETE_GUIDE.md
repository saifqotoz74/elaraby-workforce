# 1. الرؤية المؤسسية وسياق العمل

### ما هي مجموعة العربي؟
تُعد **مجموعة العربي** الصرح الصناعي والتجاري الأكبر في مصر والمنطقة في مجال تصنيع وتسويق الأجهزة المنزلية والإلكترونية (توشيبا، شارب، تورنيدو، سيكو، وهيتاشي). تمتلك المجموعة مجمعات صناعية عملاقة:
* **مجمع مصانع بنها (محافظة القليوبية):** يضم مصانع التلفزيونات، الشاشات، اللوحات الإلكترونية، والمغذيات الصناعية.
* **مجمع مصانع قويسنا (محافظة المنوفية):** يضم مصانع الثلاجات، الغسالات، أجهزة التكييف، المراوح، والمواتير.
* **شبكة مراكز الخدمة والصيانة واللوجستيات:** تغطي كافة محافظات جمهورية مصر العربية بآلاف الفنيين وسائقي أساطيل التوزيع.

### الدوافع الاستراتيجية للمشروع:
1. **القضاء على نزيف الإنتاج الناتج عن الورقيات:** كان العامل يضطر لترك خط التجميع لمدة 45 دقيقة لقطع مسافة نصف كيلومتر داخل المجمع للوصول لمبنى شؤون العاملين لتقديم طلب إجازة عارضة أو سلفة أو تصريح عيادة.
2. **عزل الصلاحيات وحماية البيانات بين المصانع (Cross-Factory Governance):** ضمان أن كل مجمع صناعي ومدير عنبر يتحكم فقط في نطاقه الجغرافي (`scope_factory: benha` أو `scope_factory: quesna`) مع منع أي تداخل بين السجلات.
3. **الشفافية المطلقة في الرواتب والاستحقاقات:** توفير قسيمة راتب مشفرة برمز PIN على هاتف العامل تشرح بالتفصيل: الراتب الأساسي، ساعات الأوفرتايم، الحوافز، استقطاعات التأمينات والضرائب، والسلف، مما أنهى تماماً طوابير التظلمات الشهرية.
4. **الامتثال لقانون العمل المصري رقم 12 لسنة 2003:** ضبط رصيد الإجازات السنوية بدقة (21 يوماً سنوياً، ترتفع تلقائياً إلى 30 يوماً لمن أتم 10 سنوات خدمة أو تجاوز سن الخمسين).

# 4. قاعدة البيانات وجداول PostgreSQL

تحتوي قاعدة البيانات على **15 جدولاً وفهرساً مخصصاً** لتحقيق التكامل العلائقي المطلق:

### 1. جدول تتبع الترحيلات `schema_migrations`
* **الأعمدة:** `version` (INTEGER PK), `name` (VARCHAR), `applied_at` (TIMESTAMPTZ).
* **الدور:** ضمان تنفيذ التعديلات البرمجية على الداتابيز بطريقة تسلسلية وغير متضاربة عبر السكربت `migrate-json-to-postgres.js`.

### 2. جدول العدادات الذرية `counters`
* **الأعمدة:** `collection` (VARCHAR PK), `current_value` (BIGINT).
* **الدور:** استبدال عدادات الذاكرة بتوليد متسلسل وآمن للأرقام المرجعية (مثل أرقام الطلبات `REQ-10024`).

### 3. جدول الموظفين المركزي `employees`
* **الأعمدة:**
  * `id` (VARCHAR(64) PK): المعرف الفريد.
  * `national_id` (VARCHAR(14) UNIQUE): الرقم القومي المصري المكون من 14 رقماً.
  * `phone` (VARCHAR(20) UNIQUE): رقم هاتف الموظف بالصيغة الدولية (`+20...`).
  * `name`, `name_en`: اسم الموظف باللغتين العربية والإنجليزية.
  * `factory` (VARCHAR(100)): المصنع التابع له (`Benha`, `Quesna`, `Headquarters`).
  * `department` (VARCHAR(100)): الإدارة أو العنبر (`Assembly Line 1`, `Quality`, `Maintenance`).
  * `job_title`: المسمى الوظيفي.
  * `pin_hash` (VARCHAR(255)): التشفير المالح لرمز الـ PIN للدخول السريع.
  * `vacation_balance` (NUMERIC(5,1) DEFAULT 21.0 CHECK (vacation_balance >= 0)): رصيد الإجازات السنوية المتبقي مع قيد يمنع النزول تحت الصفر نهائياً.
  * `role` (VARCHAR(50)): الرتبة (`employee`, `supervisor`, `hr_admin`, `super_admin`).
  * `scope_factory`, `scope_department`: نطاق الإشراف وعزل الصلاحيات الجغرافي.
  * `token_version` (INTEGER DEFAULT 1): عداد إبطال الجلسات عند تسجيل الخروج من كل الأجهزة.
* **الفهارس:** فهارس B-Tree على `national_id`, `phone`, `factory`, `department`, `active`.

### 4. جدول الطلبات والإجازات `requests`
* **الأعمدة:**
  * `id` (VARCHAR PK), `ref_number` (VARCHAR UNIQUE).
  * `employee_id` (REFERENCES employees(id) ON DELETE CASCADE).
  * `type`: نوع الطلب (`leave_annual`, `leave_casual`, `salary_advance`, `shift_swap`, `overtime_appeal`).
  * `status`: حالة الطلب (`inReview`, `pending`, `approved`, `rejected`, `cancelled`).
  * `days` (NUMERIC(5,1) CHECK (days > 0)): عدد أيام الإجازة.
  * `start_date`, `end_date`, `reason`, `rejection_reason`.
  * `decision_by`: كود المسؤول الذي اتخذ القرار.
  * `decided_at`: توقيت اتخاذ القرار.
* **الفهارس:** فهرس مركب `idx_requests_emp_status` على `(employee_id, status)` لسرعة استرجاع طلبات الموظف في أجزاء من الميلي ثانية.

### 5. جدول كشوف الرواتب الشهرية `payroll`
* **الأعمدة:**
  * `id` (VARCHAR PK), `employee_id` (REFERENCES employees(id)).
  * `month` (1-12), `year` (>= 2020).
  * `base_salary`, `allowances`, `deductions`, `net_salary` (NUMERIC(12,2)).
  * `currency` (VARCHAR DEFAULT 'EGP').
  * `breakdown` (JSONB): تفصيل الحوافز، بدل الوجبة، التأمينات، وساعات الأوفرتايم ككائن JSON عالي السرعة.
  * `status` (VARCHAR DEFAULT 'published').
* **القيود:** قيد فريد مركب `uq_payroll_emp_month_year` يمنع تكرار إصدار مفردات راتب لنفس الموظف في نفس الشهر.

### 6. جدول جداول الورديات الأسبوعية `roster`
* **الأعمدة:** `id` (PK), `employee_id`, `week_start`, `shifts` (JSONB), `notes`.
* **القيود:** `uq_roster_emp_week` يضمن جدولاً واحداً معتمداً لكل أسبوع لكل موظف.

### 7. جدول الرحلات والمصايف الاجتماعية `trips`
* **الأعمدة:** `id` (PK), `title`, `destination` (مطروح، رأس البر، الإسكندرية)، `seats_total`, `booked_employee_ids` (JSONB), `price`.

### 8. جدول المزايا وتقسيط الأجهزة `benefits`
* **الأعمدة:** `id`, `title`, `category`, `discount`, `description`.

### 9. جدول الإعلانات والتعاميم الإدارية `announcements`
* **الأعمدة:** `id`, `title`, `body`, `target_factory`, `author`, `created_at`.

### 10. جدول الأخبار العامة للمجموعة `news`
* **الأعمدة:** `id`, `title`, `body`, `image_url`, `created_at`.

### 11. جدول الإشعارات الموجهة `notifications`
* **الأعمدة:** `id`, `employee_id`, `title`, `body`, `category`, `read` (BOOLEAN DEFAULT FALSE).

### 12. جدول الشكاوى والمخاوف السرية `concerns`
* **الأعمدة:** `id`, `ref_number` (سري ومجهول), `category` (سلامة، تحرش، تظلم، احتيال), `description`, `attachment_url`, `status` (`open`, `investigating`, `resolved`).

### 13. جدول سجلات التدقيق الأمني `audit_logs`
* **الأعمدة:** `id`, `timestamp`, `actor`, `actor_role`, `action`, `target`, `details` (JSONB), `ip`, `factory`.

### 14. جدول توكنات أجهزة الموبايل `fcm_tokens`
* **الأعمدة:** `id` (SERIAL), `employee_id`, `token` (VARCHAR(500) UNIQUE), `updated_at`.

### 15. جدول ضبط وتحديث التطبيق الإجباري `app_version_config`
* **الأعمدة:** `id`, `min_version`, `latest_version`, `force_update` (BOOLEAN), `update_url`.

# 5. دليل مسارات الـ API بالكامل

يحتوي الخادم على **أكثر من 35 مساراً برمجياً** مقسمة ومحمية بدقة:

## أ. مسارات الموظف وتطبيق الموبايل
| Method | مسار الـ API | نوع الحماية | الهدف والمدخلات والمخرجات |
| :--- | :--- | :--- | :--- |
| `GET` | `/api/app-version` | عام (Public) | فحص إصدار التطبيق؛ يرجع `forceUpdate: true/false` ورابط التحديث لمنع الإصدارات القديمة. |
| `POST` | `/api/auth/otp` | محمي بالـ Rate Limit | إرسال رمز OTP؛ المدخلات: `{ identifier: "الرقم القومي أو الهاتف" }`؛ يرسل 4 أرقام عبر SMS. |
| `POST` | `/api/auth/otp/verify` | محمي بالـ Rate Limit | التحقق من صحة الكود؛ المدخلات: `{ identifier, code }`؛ يرجع `{ ok: true, hasPin: true/false }`. |
| `POST` | `/api/auth/pin` | يتطلب التحقق من OTP | تعيين رمز PIN جديد مكون من 4 أرقام مشفرة بملح عشوائي بخوارزمية PBKDF2. |
| `POST` | `/api/auth/pin/verify` | محمي بالـ Rate Limit | تسجيل الدخول برمز الـ PIN؛ يرجع توكن المصادقة `JWT Token` وبيانات الملف الشخصي. |
| `POST` | `/api/auth/pin/change` | يتطلب `Bearer JWT` | تغيير رمز الـ PIN الحالي برمز جديد بعد فحص الرمز القديم. |
| `GET` | `/api/employee/me` | يتطلب `Bearer JWT` | استرجاع بيانات الموظف الشخصية والوظيفية ورصيد إجازاته الحالي. |

# 6. تطبيق الموبايل (Flutter Deep-Dive)

### الهيكل المعماري في فلاتر
تم بناء تطبيق الموبايل باتباع **Clean Architecture (Feature-First Pattern)** لضمان الاستقلالية وسهولة الصيانة:

```
lib/
├── core/
│   ├── network/       # عميل ApiClient مع اعتراض الأخطاء وإضافة JWT Headers تلقائياً
│   ├── storage/       # LocalStore للتخزين المحلي المشفر للمسودات والجلسات
│   ├── theme/         # ألوان وتصميم العربي والتبديل التلقائي للوضع الليلي
│   ├── typography/    # إدارة الخطوط: خط Cairo للعربية وخط Inter للإنجليزية
│   └── utils/         # أدوات فحص الرقم القومي المصري ومعالجة الصور الموزعة
│
├── features/
│   ├── auth/          # دورة المصادقة: NationalIdScreen -> OtpScreen -> PinScreen
│   ├── home/          # الشاشة الرئيسية ومؤشرات الحضور والإعلانات
│   ├── services/      # شاشات الإجازات، قسيمة الراتب، السلف، وبيانات الموظف

│   └── inbox/         # شاشة الإشعارات المباشرة ونظام رفع الشكاوى السرية
│
└── l10n/              # ملفات التعريب والترجمة الرسمية (app_ar.arb و app_en.arb)
```

### توثيق الشاشات وتدفق المستخدم (User Flows)
1. **شاشة الرقم القومي (`NationalIdScreen`):**
   * إدخال الرقم القومي المكون من 14 رقماً.
   * خوارزمية تحقق حسابية تفحص صحة القرن (2 للقرن العشرين، 3 للقرن الحادي والعشرين)، كود المحافظة (من 01 إلى 88)، وتاريخ الميلاد.
2. **شاشة التحقق برمز الـ OTP (`OtpScreen`):**
   * مؤقت عد تنازلي مدته 60 ثانية قبل السماح بإعادة الإرسال.
   * تعبئة تلقائية لكود التحقق المكون من 4 أرقام فور وصول رسالة الـ SMS.
3. **شاشة رمز الـ PIN وقفل البصمة (`PinScreen` & `PinLockScreen`):**
   * إدخال وتأكيد رمز سري من 4 أرقام.
   * قفل فوري للشاشة عند الخروج من التطبيق مع دعم الفتح ببصمة الإصبع أو الوجه.
4. **شاشة قسيمة الراتب المشفرة (`SalarySlipScreen`):**
   * لا تظهر تفاصيل الراتب مباشرة؛ بل تتطلب إدخال رمز الـ PIN لحماية خصوصية العامل في صالة الإنتاج.
   * عند إدخال الرمز بنجاح، يتم عرض بطاقة راتب تفاعلية تفصل الاستحقاقات والاستقطاعات وتتيح مشاركتها كملف PDF.
5. **شاشة تقديم الإجازات (`LeaveRequestScreen`):**
   * اختيار نوع الإجازة، وتاريخ البدء والانتهاء.
   * حساب تلقائي لعدد الأيام الفعلية مع استثناء العطلات الأسبوعية ومقارنتها بالرصيد المتبقي.
   * حفظ مسودة الطلب تلقائياً في حال انقطاع الشبكة.

### نظام العمل بدون إنترنت والمسودات (Offline-First Store & Drafts)
* يدير كلاس `LocalStore` حفظ كافة استجابات الـ API محلياً.
* في حال عدم توفر اتصال بالإنترنت، يتحول التطبيق بسلاسة لوضع `UiState.offline` عارضاً البيانات المخزنة مسبقاً مع شريط تنبيه برتقالي لطيف.
* عند تقديم طلب إجازة في وضع الأوفلاين، يقوم كلاس `RequestsStore` بحفظ الطلب محلياً بعلامة `isPendingSync: true`، وبمجرد عودة الاتصال يقوم التطبيق بمزامنة الطلبات تلقائياً مع السيرفر دون فقدان أي بيانات.

# 8. نظام الطوابير والمعالجة الخلفية

لمنع أي بطء في استجابة الخادم أثناء أوقات الذروة، تم فصل كافة المهام الثقيلة في **6 طوابير مستقلة** عبر مكتبة `BullMQ` وعنقود `Redis 7+`:

```
                       [ Express HTTP Event Loop ]
                                    │
                       (إضافة المهام دون انتظار)
                                    ▼
       ┌─────────────────────────────────────────────────────────┐
       │                   BULLMQ REDIS QUEUES                   │
       ├─────────────────────────────────────────────────────────┤
       │ 1. sms-dispatch         ──► إرسال رسائل الـ OTP والتعاميم│
       │ 2. push-notifications   ──► بث إشعارات الهواتف المحمولة │
       │ 3. attendance-sync      ──► استيراد سجلات البصمة الحيوية │
       │ 4. payroll-process      ──► احتساب كشوف الرواتب الشهرية │
       │ 5. erp-sync             ──► المزامنة الثنائية مع SAP    │
       │ 6. maintenance-tasks    ──► النسخ الاحتياطي وتنظيف الكاش│
       └─────────────────────────────────────────────────────────┘
                                    │
                                    ▼
                       [ worker.js Background Daemon ]
```

* **استراتيجية إعادة المحاولة (Exponential Backoff):** في حال تعطل مزود خارجي (مثل شبكة الـ SMS)، يقوم المعالج تلقائياً بإعادة المحاولة بعد (2 ثانية، ثم 4 ثوانٍ، ثم 8 ثوانٍ).
* **طابور الرسائل الميتة (Dead-Letter Queue):** أي مهمة تفشل بعد 5 محاولات متتالية تُنقل لطابور خاص مع إرسال إشعار فوري لمهندسي التشغيل للتحقيق دون تعطيل باقي العمليات.

# 9. محولات التكامل الخارجية

تم بناء طبقة وسيطة موحدة عبر **نمط المحول (Adapter Pattern)** لفصل منطق التطبيق عن تفاصيل الشركات المزودة:

### أ. محولات رسائل الـ SMS
* كلاس الأساس `BaseSmsProvider`: يحدد العقد القياسي للدوال (`sendOtp`, `sendNotification`, `checkBalance`).
* المحولات المعتمدة:
  1. `CequensSmsProvider`: للربط مع بوابة Cequens الرائدة في مصر.
  2. `VodafoneSmsProvider`: للربط مع شبكة فودافون مصر للأعمال.
  3. `TwilioSmsProvider`: للاستخدام الدولي والرسائل الاحتياطية.
  4. `MockSmsProvider`: للتطوير المحلي وطباعة الرسائل في التيرمنال مجاناً.
* **تطبيع أرقام الهواتف:** دالة ذكية تفحص الرقم وتحوله تلقائياً للصيغة الدولية الرسمية (`01012345678` تتحول إلى `+201012345678`).

### ب. محول إشعارات Firebase (FCM v1)
* يستخدم كلاس `FirebasePushProvider` أحدث بروتوكول معتمد من جوجل (`HTTP v1`).
* يقوم المحول تلقائياً بقراءة مفتاح الخدمة `service-account.json`، وتوليد توكنات `OAuth2 Access Tokens`، وتخزينها في الكاش مع تجديدها تلقائياً قبل انتهائها بـ 5 دقائق، مما يلغي تماماً مشكلة انتهاء صلاحية مفاتيح الربط القديمة.

### ج. محولات الـ ERP (SAP & Oracle)
* كلاس `SapAdapter`: يتصل بخدمات OData الرسمية لنظام **SAP S/4HANA** لجلب بيانات الموظفين وتحديث سجلات الإجازات المعتمدة.
* كلاس `OracleAdapter`: يتصل بواجهات REST لنظام **Oracle Cloud HCM**.
* أداة الفحص الميداني: وفرنا سكربت تشغيلي مستقل `server/scripts/test-erp-connectivity.js` يمكن لمهندس الشبكات تشغيله لفحص وصول الفايروول للـ SAP قبل تفعيل النظام.

### د. محولات البصمة والتوفيق الثنائي
* كلاس `BaseBiometricAdapter`: يقوم بقراءة حركات الحضور من أجهزة **ZKTeco** و **Suprema**.
* محرك التوفيق الثنائي (`WorkforceReconciliationEngine`): يقارن بين الحضور الفعلي المسجل بالبصمة وبين جدول الورديات وطلبات الإجازات المعتمدة، ويولد تلقائياً تقريراً بالغياب بدون إذن أو التأخير.

### هـ. مزود التخزين السحابي الأصلي (AWS SigV4)
* كلاس `S3StorageProvider`: يدعم التخزين على Amazon S3، أو سيرفرات MinIO الداخلية، أو Cloudflare R2.
* **الميزة الهندسية:** كُتب كود التوقيع الرقمي المشفر `AWS Signature Version 4 (SigV4)` بالاعتماد على مكتبة التشفير الأصلية في Node.js (`crypto`) بدون الحاجة لتحميل حزمة `@aws-sdk` التي تستهلك أكثر من 80 ميجابايت من حجم السيرفر!

# 10. الأمان والامتثال وعزل المصانع

1. **جدار عزل المصانع والأقسام (Cross-Tenant Scope Gate):**
   * يتم تخزين نطاق المسؤول في الـ JWT Payload (مثل: `scope_factory: "benha"`).
   * وسيط الأمان في الباك إند يقوم باعتراض أي استعلام، ويفرض تلقائياً شرط `WHERE factory = $1` في استعلامات الداتابيز.
   * لو حاول مسؤول تعديل سجل لا ينتمي لمصنعه، يتم حجب الطلب فوراً بكود `403 Forbidden` ويسجل الحادث في سجل التسلل.
2. **منع هجمات التوقيت (Timing-Attack Defense):**
   * يتم فحص الـ PIN وكلمات المرور باستخدام دالة `crypto.timingSafeEqual` التي تستغرق نفس عدد أجزاء الميلي ثانية دائماً، مما يمنع المخترق من معرفة صحة الأرقام الأولى عبر قياس زمن الاستجابة.
3. **تطهير سجلات المراقبة من البيانات الحساسة (PII Scrubbing):**
   * محرك الـ Logger المطور في `server/src/observability/` يقوم بفحص أي كائن قبل طباعته في السجلات، ويستبدل تلقائياً مفاتيح `password`, `pin`, `token`, `nationalId`, `otp` بالقيمة المحجوبة `[REDACTED]`.
4. **بوابة حماية النسخ الاحتياطية (Cryptographic Backup Integrity):**
   * عند أخذ نسخة احتياطية من الداتابيز، يتم حساب بصمتها الرقمية عبر خوارزمية `SHA-256` وتخزينها في ملف منفصل `.manifest.json`.
   * عند الاسترجاع، يقوم سكربت `restore-database.js` بمطابقة الهاش، ويرفض استرجاع الملف إذا تم العبث بمحتواه أو تضرره.

# 11. بيئة التطوير مقابل بيئة الإنتاج الصارمة

تطبيقاً للقاعدتين الذهبيتين في الهندسة المؤسسية:
* **القاعدة A (No Fake Readiness):** عدم ادعاء الجاهزية بدون وجود كود واختبارات حقيقية.
* **القاعدة B (No Silent Fallbacks in Production):** منع السقوط الصامت لوضع الـ Mock في الإنتاج.

| المكون البرمجي | تصرف السيرفر في وضع التطوير (`NODE_ENV=development`) | تصرف السيرفر في وضع الإنتاج (`NODE_ENV=production`) |
| :--- | :--- | :--- |
| **قاعدة البيانات** | يسمح بقراءة ملف `db.json` لتسهيل عمل المطور محلياً بدون داتابيز. | **يرفض التشغيل تماماً ويغلق السيرفر** إذا لم يتوفر رابط PostgreSQL صحيح. |
| **خادم الكاش** | يشغل `InMemoryRedisMock` في رامات السيرفر بدون خطأ. | **يرفض التشغيل تماماً ويغلق السيرفر** إذا لم يتوفر اتصال بعنقود Redis 7+ حقيقي. |
| **كلمة سر الأدمن** | يسمح بكلمة السر الافتراضية `elaraby2026`. | **يرفض الإقلاع** لو كلمة سر الأدمن الافتراضية لم تُغير لكلمة معقدة من 12 حرفاً على الأقل. |
| **مفتاح الـ JWT** | يولد مفتاحاً تلقائياً أو يستخدم مفتاح الماكينة. | **يرفض الإقلاع** لو لم يتم توفير مفتاح تشفير قوي ومعقد بطول 32 حرفاً على الأقل. |
| **فحص الجاهزية `/readiness`** | يعيد جاهزية تامة للتطوير. | يفحص الاتصال الحي الحقيقي ويعيد `503 Service Unavailable` لو انقطعت الداتابيز. |

# 13. دليل التشغيل والنشر وإدارة الأزمات

### أوامر التشغيل الأساسية:
```bash
# تشغيل خادم الـ API في وضع التطوير
cd server
npm run dev

# تشغيل خادم معالجة الطوابير في وضع التطوير
cd server
npm run worker:dev

# تشغيل فحص الأمان والتحقق من عدم تسريب أسرار
cd server
npm run audit:secrets

# ترحيل البيانات من JSON إلى PostgreSQL
cd server
node scripts/migrate-json-to-postgres.js --execute

# تشغيل عنقود الإنتاج بالكامل عبر Docker
docker compose -f docker-compose.production.yml up -d
```

### خطة التصرف السريع في حالات الطوارئ (Incident Triage):
1. **انقطاع الاتصال بقاعدة بيانات PostgreSQL:**
   * يعيد السيرفر فوراً كود `503 Service Unavailable` في فحص الجاهزية `/readiness`.
   * مجمع الاتصالات في `postgres.js` يعيد المحاولة تلقائياً كل 5 ثوانٍ مع تراجع أسي (Exponential Backoff).
2. **تراكم مهام في طابور الـ SMS أو الإشعارات:**
   * افتح لوحة التحكم أو افحص حجم الطابور: `redis-cli LLEN bull:sms-dispatch:wait`.
   * قم بزيادة عدد خوادم الـ Worker أفقياً: `docker compose scale worker=4`.
3. **محاولة اختراق أو تخمين كلمة سر الأدمن:**
   * يقوم وسيط `rateLimit.js` بقفل الـ IP تلقائياً لمدة 15 دقيقة بعد 5 محاولات فاشلة، مع تسجيل الحادث في جدول `audit_logs`.
